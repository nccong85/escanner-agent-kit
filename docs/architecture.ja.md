# アーキテクチャ

## 設計目標

1. **有界なループ。** 無意味なレビューラウンドを行いません。
2. **本物の指摘。** 誤った指摘（指摘とはレビュアーが報告する欠陥です）は、コーダーの実行 1 回と再レビュー 1 回のコストを生みます。
3. **事実を重複させない。** エージェントがそれぞれプロジェクトを学び直すと、トークンが無駄になります。

## コンポーネント

| コンポーネント | 役割 | 決定的か |
|---|---|---|
| `review_brief.md` Part A | すべてのエージェントが最初に読むプロジェクトの事実 | — |
| `review_brief.md` Part B | プロトコル：重大度ゲート、スコープ、差分レビュー、担当、レポート上限、ハンドオフ | — |
| `review_rules.md` | ルール ID の閉じた集合 | — |
| `routing.md` | ディレクトリ → エージェント、オーバーレイゲート、担当 | — |
| `validate_rule_ids.sh` | ルール ID が存在しない指摘を破棄します | **はい** |
| `validate_findings.sh` | 存在しないものを引用している指摘を破棄します | **はい** |
| `validate_spec_refs.sh` | 存在しないファイルや未知のエージェントを引用する仕様 (spec)/タスクを不合格にします | **はい** |
| `validate_citations.sh` | リンク切れや捏造された URL にフラグを立てます | **はい** |
| `block_destructive_git.sh` | コミットされていない作業を破棄する git コマンドをブロックします | **はい** |
| `finding-checker` | 1 つの指摘を diff の変更箇所 1 つ（hunk）に照らして判定します | モデル |
| 領域別レビュアーとゲート | diff をレビューします | モデル |
| `device-tester` + ドライバー | 実機でビルドを実行し、ケースごとに証拠を報告します | ドライバーは **はい**、エージェントはモデル |

## 各ルールが存在する理由

- **Critical/High のみがブロックします。** Medium/Low は保留され、最終レビューで一度だけトリアージされます。そうしないと毎ラウンド新しい細かい指摘が出て、件数が収束しません。
- **ラウンド 2 からは差分レビュー。** 再レビューは修正だけを確認します。ラウンド 1 で見逃された欠陥は、ループを延ばす代わりに後で扱います。
- **リグレッションではない新しいブロッカーが出たら実行を止めます。** 正しい修正でもなお新しいブロッカーが出るなら、仕様 が間違っており、コードをさらに変更しても解決しません。
- **ルール ID。** 構造化出力が固定するのは指摘の*形式*であり、*正しさ*ではありません。既存のルールを必須にすることで、レビュアーが基準をでっち上げるのを防ぎます。
- **フィルターは主張と hunk だけを見ます。** 作者の推論を読んだレビュアーはそれに引きずられます。セカンドオピニオンは独立していてこそ価値があります。フィルターは非対称です。データ損失・プライバシー・クラッシュは再現率優先、パフォーマンスは証拠優先、それ以外はすべて適合率優先です。
- **欠陥の種類ごとに担当エージェントは 1 つ。** 各関心事について指摘を出すのは 1 つのエージェントだけです。2 人のレビュアーが同じ指摘を出すとコストが倍になり、矛盾する修正を生みます。
- **固定のハンドオフブロック。** オーケストレーターは推測せず、`ACTION:` 行をパースします。
- **コミットではなくスナップショットと比較します。** タスク間では通常コードがコミットされないため、`git diff <sha>..`は常に空です。そこでコーダーが編集する前に、パイプラインは `git stash create` でファイルのスナップショットを取ります。編集後にスナップショットと比較し、いま変更された内容を正確に得ます。コーダーがタスクのスコープ外のファイルを編集した場合、パイプラインはスナップショットから元の内容を復元します。スナップショットには新規作成ファイルが含まれないため、レビュアーにはその一覧も渡します。
