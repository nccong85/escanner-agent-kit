# 現場メモ

実際のプロジェクトでこのレビューループを運用して得た教訓です。

1. **誤ったツール名は黙って無視されます。** エージェントは `tools:` に `serena` と `context7` を列挙していました。Claude Codeが期待するのは `mcp__serena__*` / `mcp__context7__*` なので、素の名前では何も許可されず、サブエージェントはMCP をまったく使えないように見えました。
2. **未知の frontmatter フィールドは何もしません。** `allowed_commands`、`displayName`、`category` は何も制限していませんでした。本当に制限するには、Claude Code がサポートする仕組みが必要です。
3. **レビュアーはアンカーをでっち上げます。** `R-PIT-8.12` のような引用はもっともらしく見えましたが、存在しませんでした。ルール IDバリデーターはモデルを呼び出さずにそれらを却下しました。
4. **ビルドできるスイートが実行されるスイートとは限りません。** 74 件の C++ テストケースが、一度も実行されないまま合格を報告していました。実際に実行すると、範囲外読み取りと、決して失敗し得ないガードテストが見つかりました。フィクスチャが契約自身の正規化を破っていたためです。
5. **テストヘルパーが変更を元に戻すために `git checkout -- <file>` を使い**、そのファイルにあった別タスクの未コミットの編集を消してしまいました。プロンプトのルールでは防げなかったため、現在はフックがこのコマンドをブロックします。
6. **文書化された差分レビューの基準点が間違っていました。** ワークフローはレビュアーに `git diff <sha>..` を読むよう指示していましたが、これはコミット同士を比較するため、チームがタスク間でコミットしない場合は常に空です。オーケストレーターは`git stash create` のスナップショットで回避していましたが、これは未追跡ファイルを含みません（1 つの機能で新規ファイル 57 件）。そのためレビュアーには修正で作成されたファイルの明示的な一覧も必要です。現在のワークフローは両方を明記しています。
7. **フックは無害な `grep "git restore"` をブロックし、その一方で `git "stash"` を通していました。** シェルのテキストに対する正規表現は両方向に失敗します。現在のフックは bash/zsh と同じ方法でコマンドを読むため、引用符内のテキストは、シェルが実行する場合（`sh -c`、`eval`、`$(…)`、シェルに渡されるヒアドキュメント）を除きデータとして扱われます。
8. **小さな作業は自分でやるほうが速いです。** 定型的な修正にコーダーエージェントを派遣するのはやめましょう。パイプラインは機能開発のためのもので、1 行の変更のためではありません。
